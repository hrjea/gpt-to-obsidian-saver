# Permissions

| Permission | Code Location | Purpose | Data Involved | Optional or Required | Effect If Removed |
| --- | --- | --- | --- | --- | --- |
| `storage` | `content.js`, `options.js`, `background.js` | Store and read extension settings. | Language, vault name, folder path, toggles, local vault path, HTML attachment folder. | Required | Options cannot persist and content/background scripts cannot read save settings. |
| `nativeMessaging` | `background.js` | Call the local native helper for direct vault writes and HTML attachments. | Save payloads, note content, attachment metadata, downloaded HTML source path for the active save. | Required for native-helper mode | Direct file saving and HTML attachment copying fail; URI mode may still work for normal notes. |
| `downloads` | `background.js`, `content.js` | Identify one exact current HTML or generated detailed-Markdown download associated with the active Save action. | Download ID, expected filename, local path, and start/end time for a bounded `.html`, `.htm`, or `.md` watch. | Required for Chrome downloads fallback | Page-readable extraction can still work, but click-only/sandboxed artifact downloads cannot be copied into the Vault. |
| `clipboardRead` | `manifest.json`, `background.js`, `content.js` | Read one freshly copied ChatGPT share URL during an explicitly approved ordinary supplemental-link or specialized remote-reference flow when the URL is not available in the page DOM. A verified missing-only hydration window skips the request instead of recovering inside the consent callback. | One clipboard string, read only after a strict current-action copy-success signal; only a validated ChatGPT share URL may enter a note. | Optional and requested at runtime | The extension uses its own empty manual URL field or stops the save; required local capture permissions are unchanged. |
| `https://chatgpt.com/*` | `manifest.json`, `content.js` | Inject Save to Obsidian UI and read user-selected ChatGPT message content. | ChatGPT page DOM content involved in a user-initiated save. | Required | The extension cannot run on the current ChatGPT domain. |
| `https://chat.openai.com/*` | `manifest.json`, `content.js` | Support the older ChatGPT domain. | Same as above. | Required for older-domain support | The extension cannot run on the older ChatGPT domain. |

The downloads permission is used only for a bounded watch tied to the active Save action and expected HTML or detailed-Markdown filename. The exact matching file can then be copied/read by the local Native helper. The extension does not scan, upload, or transmit unrelated files from the Downloads folder.

`clipboardRead` is not a required install-time permission. Version 1.5.52 adds no permission and does not make `clipboardRead` required. Every ordinary save now asks explicit ChatGPT Share consent; cancellation creates no note and makes zero permission or Share requests. On Continue, the optional permission request is made synchronously from that consent action only after the immediate runtime, selected-turn, route, and approved-control guard passes. The consent, request, clipboard read, and use of its value are bounded to that approved attempt, and the clipboard is read at most once after a fresh strict Copy-success signal. Chrome's granted optional permission itself may remain available until the user or browser revokes it; the extension does not automatically remove it. The raw value is never logged, stored separately, or persisted.

If the guard finds the narrow verified missing-only hydration window described in [public architecture](architecture.md), the consent callback makes zero permission requests and performs no scroll or recovery. Its one bounded recovery may run only after approved consent, and permission is not requested automatically afterward. Permission denial or skipped permission must not cause broad clipboard polling or weaker URL validation. The extension-owned manual field starts empty.

Creating, updating, reusing, or copying a ChatGPT share link is a separate remote side effect performed through ChatGPT's visible UI after consent; it is not caused by a host permission or a new private API. See [Privacy](privacy.md), [public architecture](architecture.md), and [Native Messaging documentation](native-messaging.md).
